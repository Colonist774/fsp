# FSP
Основная идея: в одном месте собрать профиль спортсмена, соревнования, регистрацию, результаты и рейтинг. Для онлайн-соревнований дополнительно сделана полноценная отправка решений с автоматической проверкой кода.

## Что есть в проекте

Для спортсмена:

- регистрация и авторизация;
- профиль с ФИО, городом, учебным заведением, дисциплинами и спортивным разрядом;
- настройки приватности для ФИО и города;
- список соревнований и регистрация на них;
- личная статистика и история участия;
- общий рейтинг спортсменов;
- просмотр результатов соревнований;
- решение задач прямо на платформе;
- возможность поиска напарника/команды через профили участников из рейтинга.

Для организатора:

- создание соревнований в виде черновика и их публикация;
- отдельные правила/инструкция для соревнования;
- просмотр зарегистрированных участников;
- просмотр отправленных решений и ручная оценка в баллах;
- внесение результатов для внешних соревнований(когда задания выполняются не на платформе ФСП);
- создание задач, примеров и скрытых тестов;
- настройка количества баллов за задачу;
- создание и редактирование статей в разделе "Анонсы";
- управление спортивными разрядами участников;
- выдача прав организатора другим пользователям.

Для соревнований, которые проходят на платформе, места рассчитываются автоматически по принятым решениям. После завершения соревнования результат фиксируется в профиле участника и учитывается в рейтинге.

## Онлайн-проверка решений

Автопроверка не была обязательной частью основного кейса, но я решил сделать её, чтобы онлайн-соревнование можно было провести внутри платформы.

Поддерживаются:

- Python;
- JavaScript;
- C++;
- Java.

Каждое решение запускается в отдельном Docker-контейнере без доступа к сети. Для контейнера ограничены память, CPU, количество процессов, время выполнения и объём вывода.

C++ и Java компилируются один раз на отправку, после чего готовая программа прогоняется по скрытым тестам.

Если организатор меняет скрытые тесты, сохранённые решения автоматически перепроверяются. Старый результат не учитывается, пока решение не будет проверено на актуальной версии тестов.

Решение, отправленное до окончания соревнования, учитывается даже в том случае, если проверка закончилась уже после дедлайна. Финальные результаты не фиксируются, пока есть такие незавершённые проверки.

## Рейтинг

Рейтинг складывается из двух частей:
- баллы за соревнования
- баллы за спортивный разряд/звание

Количество баллов за место зависит от уровня соревнования. В системе используются пять уровней:

1. региональное;
2. чемпионат / кубок региона;
3. межрегиональное;
4. всероссийское;
5. чемпионат / кубок России.

Чем выше уровень соревнования и итоговое место, тем больше баллов получает спортсмен. Баллы начисляются за места с 1-го по 10-е.

Спортивный разряд/звание даёт отдельный фиксированный бонус.

Полная таблица баллов есть в интерфейсе на странице «Как считается рейтинг».

## Основной сценарий

Самый показательный сценарий для проверки проекта:

1. Организатор создаёт черновик соревнования.
2. Добавляет задачи, примеры, скрытые тесты и баллы.
3. Публикует соревнование.
4. Спортсмен регистрируется, после старта открывает задачи и отправляет решения.
5. Judge автоматически проверяет код. При необходимости организатор открывает отправку и выставляет ручную оценку.
6. Из лучших результатов по задачам формируются текущие баллы и места.
7. После окончания соревнования результаты фиксируются.
8. Результат появляется в профиле спортсмена и меняет его рейтинг.

Для внешних соревнований организатор вместо автопроверки вручную указывает итоговые места участников.

## Демо-данные

Для защиты можно одной командой создать 15 задач, будущие онлайн/офлайн соревнования и отдельный завершённый контест с участниками, решениями и итоговой таблицей:

```bash
cd backend
python -m app.case_demo_seed
```

Тестовые аккаунты используют пароль `FspDemo2026!`:

- организатор — `demo_organizer`;
- спортсмены — `demo_ivan`, `demo_sofia`, `demo_timur`.

Скрипт можно запускать повторно: демонстрационный контест второй раз не создаётся.

## Дополнительно

Завершённое соревнование нельзя редактировать, а задачу нельзя удалить после старта. Это сделано специально, чтобы после публикации результатов не менялась история соревнования.

Код отправленных решений хранится 30 дней после окончания соревнования, после чего очищается. Метаданные отправки и итоговый результат остаются в базе.

Участник с нулевым результатом(количеством решенных задач) не получает баллов за занятое место(например, если всего 3 участника, решив 0 задач, участник займет минимум 3 место, но баллы за соревнование не получит). При одинаковом количестве баллов используется спортивное ранжирование: например, результаты `500, 500, 300` дают места `1, 1, 3`.
